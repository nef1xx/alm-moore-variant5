# Контекст проекта для следующего агента

Это самостоятельный учебный проект АЛМ, вариант 5, автомат Мура. Прочитайте README.md, docs/DECISIONS.md, docs/01_source.md и docs/08_hardware.md перед изменением логики.

## Соглашения, которые нельзя потерять

- `^X` исходного задания означает отрицание, не XOR. Порядок битов: X1 X2 X3 X4; F1 F2 F3; Y1 Y2 Y3 Y4 Y5; q2 q1 q0.
- Пользователь подтвердил: в ЛСА условная ↑ выполняется при A=1. A1=(F2=1), A2=(F2=0), A3=(F3=1), A4=A5=(F1=0). Отдельная ↑ — безусловный переход.
- Основная схема: состояния S0..S6, конец S6 поглощающий до синхронного RESET. Код 111 — неиспользуемый и за один такт восстанавливается в S0.
- Дополнение 04b/05c использует циклическую учебную трактовку: начало и конец S0, всего 6 состояний. Не подменяйте этим вариантом основную аппаратную реализацию без согласованного изменения всех формул, данных и проверок.
- Один tick — один фронт CLK и один переход между состояниями Мура. Все условия между операторными вершинами используют один снимок F. X могут меняться между тактами.
- Сигналы Y в каждом состоянии — полная маска, не накопительное выставление отдельных битов.
- Реальные F(X) только 001,010,101,111. Основной граф и аппаратные уравнения определены на всех 8 формальных сочетаниях F. Ветка S5->S4 недостижима при F(X), но есть в формальном графе.
- Имена S2/S1/S0 в gate_netlist — входы установки разрядов RS, а не индикаторы состояний. Индикаторы состояний называются z0..z7. Различие объяснено в этапе 8.

## Файлы и воспроизведение

- `ulu/logic.py`: исходные и минимизированные функции.
- `ulu/reference.py`: независимые интерпретаторы; не заменять вызовом `next_state`.
- `ulu/model.py`: поведенческая модель.
- `ulu/netlist.py`: список вентилей и модель RS-регистра.
- `ulu/minimize.py`: точный сертификат минимальной ДНФ.
- `scripts/build_data.py`: проверяет и пересоздаёт CSV/JSON.
- `scripts/build_diagrams.py` + `svg_tools.py`: создают все SVG, включая схемы каждого вентиля.
- `scripts/render_assets.cjs`: SVG->PNG через sharp; `npm install`, затем `npm run render`.
- `tests/test_ulu.py`: `python -m unittest discover -s tests -v`.
- `docs/SCHEMES.md`: галерея; docs/WORKLOG.md — процесс выполнения.

После логических изменений выполните unittest, build_data.py, build_diagrams.py и обновите PNG. Осмотрите изменённые схемы, особенно условия стрелок, инверсии, метки на линиях и группы Карно. Проверка данных в GitHub Actions должна проходить без diff.

Для работы с существующими схемами редактируйте SVG-генераторы. Отчёт не должен зависеть от абсолютных путей конкретного компьютера. Не добавляйте в репозиторий авторизационные данные, исходный чужой Word-пример, временные файлы и директории analysis/stage1.
