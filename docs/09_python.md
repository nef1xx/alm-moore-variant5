# 9 Программная модель на Python

Программа содержит два уровня описания одного устройства и независимый эталон. Класс `Moore` вычисляет переход по состоянию и F. Класс `Hardware` вычисляет каждый вентиль схемы, получает входы S/R, затем обновляет три триггера. `reference.py` непосредственно исполняет исходный список пунктов, не обращаясь к функции перехода модели.

## Файлы программы

| Файл | Назначение |
|---|---|
| [logic.py](../ulu/logic.py) | Исходные и минимизированные F, проверка входов |
| [model.py](../ulu/model.py) | Состояния, выходы, поведенческий автомат |
| [netlist.py](../ulu/netlist.py) | Вентили и три RS-триггера |
| [reference.py](../ulu/reference.py) | Эталон исходного алгоритма и ЛСА |
| [minimize.py](../ulu/minimize.py) | Полный поиск минимальной ДНФ |
| [cli.py](../ulu/cli.py) | Командная строка, ввод на каждом такте, CSV/JSON |

## Запуск

Откройте терминал в корне репозитория. Для модели достаточно Python 3.10+ без сторонних библиотек.

```bash
python -m ulu.cli --demo
python -m ulu.cli --interactive
```

В Windows можно заменить `python` на `py`. Интерактивный ввод: `0100` или `0 1 0 0` означает X1=0,X2=1,X3=0,X4=0. Команда `r` выполняет такт с RESET=1, `q` завершает программу. Другие значения отвергаются с объяснением.

Входы вводятся заново перед каждым тактом, поэтому можно вывести автомат из ожидания и из циклического участка. В состоянии S6 программа продолжает принимать входы, показывая удержание конца до `r`. Достижение конца и закрытие консоли — разные действия.

```bash
python -m ulu.cli --sequence 0100,0100,1010,1000,1000,0111,0100,1010,0100 --csv trace.csv --json trace.json
python -m ulu.cli --model behavior --demo
python -m ulu.cli --model behavior --cyclic --demo
```

`--model hardware` установлен по умолчанию. Параметр `--cyclic` разрешён только для поведенческой модели, чтобы не выдать основной список вентилей за циклическую схему.

## Значение одного такта

1. Сохраняются текущие q и выходы Y(q).
2. Из выбранного X вычисляются F.
3. По текущим q,F и RESET вычисляются все комбинационные цепи, включая S/R.
4. На фронте CLK три триггера одновременно принимают новые значения.
5. Выходы пересчитываются по новому состоянию.

Строка трассы показывает и значения до, и значения после фронта. Таким образом, момент выдачи выходов Мура виден явно. Переходы через несколько условных ромбов не добавляют отдельных тактов.

## Проверочный сценарий

| Такт | X | F | Состояние до | После | Y после |
|---:|---|---|---|---|---|
| 1 | 0000 | 111 | S0 | S0 | 00000 |
| 2 | 0100 | 101 | S0 | S1 | 10101 |
| 3 | 0100 | 101 | S1 | S2 | 01010 |
| 4 | 1010 | 111 | S2 | S4 | 10001 |
| 5 | 1000 | 010 | S4 | S5 | 01101 |
| 6 | 1000 | 010 | S5 | S5 | 01101 |
| 7 | 0111 | 001 | S5 | S3 | 10010 |
| 8 | 0100 | 101 | S3 | S4 | 10001 |
| 9 | 1010 | 111 | S4 | S5 | 01101 |
| 10 | 0100 | 101 | S5 | S6 | 00000 |
| 11 | 0100 | 101 | S6 | S6 | 00000 |

Этот пример посещает все семь состояний, проверяет начальное ожидание, петлю S5, возврат к пункту 5 и завершение. Полные значения S/R есть в [demo_trace.json](../data/demo_trace.json); [CSV](../data/demo_trace.csv) удобно открыть в электронной таблице.

![Временная диаграмма](../diagrams/09_timing.png)

При повторном S5 выходы остаются 01101 весь такт; непрерывный сигнал Y не превращается автоматически в импульс. Если исполнительное устройство требует импульсы, это было бы дополнительным требованием к нему, которого в исходном задании нет.
