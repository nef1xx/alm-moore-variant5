# 10 Проверка и воспроизводимость

Проверки сопоставляют разные способы описания устройства. Поведенческая модель, эталон команд и модель вентилей написаны отдельно, чтобы одинаковая ошибка одной таблицы не стала единственным основанием для вывода о правильности.

## Что проверено

| Проверка | Объём | Результат |
|---|---:|---|
| Исходные F против минимизированных и вентилей | 16 наборов X | Совпадение |
| Минимальность ДНФ | Все кубы и покрытия простых импликант | Стоимости (4,8), (2,3), (3,3) |
| ЛСА против исходного алгоритма | 88 случаев следующего оператора/конца/ожидания | Совпадение |
| Поведенческая модель против исходного алгоритма | 8 кодов × 8 F × 2 RESET × 2 режима | Совпадение |
| RS-схема против исходного алгоритма | 8 кодов × 8 F × 2 RESET | Совпадение |
| Полная схема X→F→автомат | 8 кодов × 16 X × 2 RESET | Совпадение |
| Независимость Y от X | 8 кодов × 16 X | Подтверждена |
| Сокращённые Y из решения 08h | Все 8 кодов | Совпадение с таблицей выходов |
| Сокращённые S/R из решения 08h | 8 кодов × 8 F × 2 RESET | Совпадение с эталонными переходами и вентильной схемой |
| Запрещённое S=R=1 | Каждый разряд во всех формальных случаях | Не возникает |
| Эквивалентные входы D | Все формальные состояния/F/RESET | Тот же следующий код |
| Длинные последовательности | 100 сценариев по 100 тактов | Совпадение трёх моделей |
| Сброс, удержание конца, ожидание, код 111 | Отдельные проверки | Пройдено |
| Список вентилей | Уникальные имена, нет циклов в комбинационной части | Пройдено |

Длинные последовательности воспроизводимы: используется фиксированный seed=5. Перебор всех однотактных переходов важнее произвольного количества примеров: при одинаковом исходном состоянии и одной входной последовательности он устанавливает эквивалентность последовательностей состояний по индукции.

## Команды воспроизведения

```bash
python -m unittest discover -s tests -v
python scripts/build_data.py
python scripts/build_diagrams.py
```

Первые две команды используют только стандартную библиотеку. Построение SVG также не требует дополнительных пакетов. Для пересоздания PNG нужен Node.js и пакет sharp:

```bash
npm install
npm run render
```

Версия sharp зафиксирована в package.json. Исходные SVG и PNG уже включены в репозиторий, поэтому просмотр и запуск модели не требуют Node.js. SVG можно открыть в редакторе векторной графики или браузере.

Для необязательной пересборки PDF-альбома после генерации PNG:

```bash
python -m pip install -r requirements-artifacts.txt
python scripts/build_pdf.py
python scripts/build_derivation_pdf.py
python scripts/build_gallery.py
```

Генераторы PDF используют Arial в Windows или DejaVu Sans в Linux. Другой TTF с кириллицей можно передать через переменную окружения ALM_FONT_REGULAR. Альбом содержит титульную страницу и 20 иллюстраций; подробный текст этапов находится в Markdown. Отдельный build_derivation_pdf.py набирает решение 08h с формулами через Matplotlib mathtext; его исходник — docs/08h_output_rs_derivation.md.

GitHub Actions запускает unittest и повторное построение данных. После `build_data.py` проверяется отсутствие изменений в data: это контролирует согласованность опубликованных таблиц с кодом.

## Проверка изображений

Схемы построены в SVG, затем преобразованы в PNG и просмотрены. Проверялись направления и условия стрелок, сохранение переходов 9→10→11 и 12→5, отсутствие меток поверх проводов, инверсии вентилей, подключения через имена цепей и группы Карно через край.

Генератор схем проверяет, что каждый вентиль из модели присутствует хотя бы на одном листе аппаратной схемы. PNG являются визуализацией SVG, а таблица вентилей сохраняется в JSON для независимого чтения другим агентом.

## Границы проверки

Модель синхронная, с установившимися входами перед фронтом. Задержки распространения, метастабильность, уровни напряжения и конкретные микросхемы не моделируются. Проверка относится к логическому проекту, формулам и цифровой модели, а не к собранной физической плате.

Учебный циклический режим проверен на уровне поведенческого автомата и исходного интерпретатора с возвратом конца в S0. Основной список вентилей реализует остановку в S6. Это различие намеренно указано в файлах и CLI.
